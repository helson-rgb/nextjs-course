# Conditional Rendering & Lists

Rendering the right content at the right time is the core of any dynamic UI. React gives you three tools for conditional output and one pattern for arrays — all using plain JavaScript with no special syntax.

## Ternary: one branch or the other

The ternary operator renders one of two values based on a condition:

```jsx
{isLoggedIn ? <Dashboard /> : <LoginPrompt />}
```

Use ternaries when both branches produce output. If the false branch renders nothing, `&&` is cleaner.

You can also ternary between different looks for the same element:

```jsx
<button className={isActive ? 'btn-primary' : 'btn-ghost'}>
  {isActive ? 'Active' : 'Inactive'}
</button>
```

Keep ternaries in JSX short. When the condition or either branch grows past one line, extract it into a variable before the return:

```jsx
const content = isLoggedIn ? <Dashboard /> : <LoginPrompt />;

return <main>{content}</main>;
```

## && short-circuit: render or nothing

When you only want to render something in the true case, short-circuit with `&&`:

```jsx
{hasError && <ErrorBanner message={error.message} />}
{isAdmin && <AdminPanel />}
```

React ignores `false`, `null`, and `undefined` — they produce no DOM output. `&&` works because JavaScript evaluates `false && anything` as `false`, which React skips.

**The 0 trap.** The left operand should be a boolean, not a number. If it's `0`, React renders the digit "0":

```jsx
// ❌ Renders the string "0" when the array is empty
{items.length && <List items={items} />}

// ✅ Convert to boolean first
{items.length > 0 && <List items={items} />}

// ✅ Or use a ternary with null
{items.length ? <List items={items} /> : null}
```

The same applies to any falsy number. Keep the left side a strict boolean — `count > 0`, `Boolean(value)`, or a double-bang `!!value`.

## Early return: render nothing at all

A component can return `null` to opt out of rendering entirely. This is useful for guards — components that need a precondition to produce any output:

```jsx
function SuccessBanner({ message }) {
  if (!message) return null; // nothing added to the DOM

  return (
    <div className="banner banner--success">
      {message}
    </div>
  );
}
```

Returning `null` does not remove the component from the React tree — hooks still run, subscriptions still fire. It simply produces no DOM nodes. Use it when the component legitimately has nothing to show, not as a way to skip expensive side effects.

## Rendering lists with .map()

To render an array, call `.map()` and return JSX for each item:

```jsx
const names = ['Alice', 'Bob', 'Carol'];

return (
  <ul>
    {names.map(name => (
      <li key={name}>{name}</li>
    ))}
  </ul>
);
```

Each item in the `.map()` callback can be as complex as you need — a full component, multiple elements in a Fragment:

```jsx
{products.map(product => (
  <React.Fragment key={product.id}>
    <dt>{product.name}</dt>
    <dd>{product.price}</dd>
  </React.Fragment>
))}
```

The `.map()` call is just a JavaScript expression — it lives inside `{}` in JSX the same way any expression does.

## Why every list item needs a stable key

React uses keys to track which items changed, were added, or were removed between renders. Without them, React falls back to comparing by position — and that causes subtle, hard-to-debug bugs.

```jsx
// ❌ No key — React matches items by position
{items.map(item => <Row label={item.label} />)}

// ✅ Stable key — React tracks each item by identity
{items.map(item => <Row key={item.id} label={item.label} />)}
```

### The input-shifts-when-deleting bug

Here's what goes wrong without stable keys. Three rows with uncontrolled inputs, keyed by index:

```
Index 0 → Alice  [input: ""]
Index 1 → Bob    [input: "typed text"]   ← user typed something
Index 2 → Carol  [input: ""]
```

You delete Bob. React reconciles the new array `[Alice, Carol]` against the old `[Alice, Bob, Carol]` **by position**:

- Position 0 → Alice: same, keep the DOM node.
- Position 1 → Carol: **was Bob** — React reuses Bob's DOM node for Carol. The input DOM node is reused too, so "typed text" is still in it.
- Position 2 → gone.

Carol's row now shows Bob's typed content. The DOM state leaked.

With `key={item.id}`:

- key `"alice"` → Alice: same, kept.
- key `"bob"` → gone: **destroyed with its DOM node**, input cleared.
- key `"carol"` → Carol: same, untouched.

The correct content stays in the correct row.

<Callout type="info">
**When index-as-key is safe:** If the list is purely static — never reordered, never items removed from the middle — and rows contain no internal state (no inputs, no focus, no animations), using the array index as a key is fine. Examples: a read-only list of labels, a static reference table, a paginated list that fully replaces on page change. The bug only surfaces when React reuses a DOM node that holds state the user has modified. If none of your rows have internal state, there is nothing to leak.
</Callout>

**Rules for keys:**

- **Unique** among siblings in the same list (not globally).
- **Stable** — the same data item must get the same key on every render.
- **Not the array index** when items can be deleted, added, or reordered.

Good key sources: database IDs, UUIDs, slugs, stable content hashes. If incoming data lacks IDs, attach them before the data enters state — never generate them inside `.map()` with `Math.random()` or `Date.now()`, as a new key on every render is equivalent to no key.

Both panels render the same list and the same `Row` component (with an uncontrolled input). The only difference is the key: index on the left, stable ID on the right.

**Experiment:** type something into Bob's input in *both* panels, then click × next to Bob. In the left panel Carol's row now shows Bob's text — the DOM state leaked. In the right panel Carol's row is unaffected.

Because `results` is always in sync with both, the `&&` / ternary for the empty state works automatically. ## Key takeaways

<Callout type="tip">
**Three tools for conditional output.** Ternary (`condition ? a : b`) when both branches render something. `&&` when only the true branch renders something — but keep the left side a boolean to avoid the "0 renders as text" trap. Early `return null` when a component has nothing to show at all.

**`.map()` is the only list primitive.** Return JSX from the callback; the resulting array drops into `{}` like any expression. Extract the callback into a named function when it grows past two or three lines.

**Keys are identity, not order.** React uses keys to match items across renders. Without stable keys, React reconciles by position — reusing DOM nodes for the wrong items and leaking state (like typed input values) into the wrong rows.

**Use database IDs, slugs, or UUIDs as keys.** Never `Math.random()` or `Date.now()` inside `.map()` — a new key on every render destroys and recreates the DOM node on every render. The array index is safe only when the list is static and rows carry no internal state.
</Callout>
