# Forms & Controlled Inputs

A form is controlled when React owns the input's value — the state is the single source of truth and every keystroke flows through it. An uncontrolled form lets the DOM manage the value and you read it with a ref or `FormData` only when you need it (usually on submit).

## Controlled vs uncontrolled

```jsx
// Uncontrolled — DOM owns the value
function Uncontrolled() {
  const ref = useRef();
  return <input ref={ref} defaultValue="hello" />;
}

// Controlled — React owns the value
function Controlled() {
  const [value, setValue] = useState('hello');
  return <input value={value} onChange={e => setValue(e.target.value)} />;
}
```

With a **controlled** input, `value` is always the state. React sets it on every render, so the displayed text is always in sync with what's in state. Removing `onChange` would make it read-only — React would fight the browser on every keystroke. Removing `value` turns it back into an uncontrolled input (and logs a warning).

With an **uncontrolled** input, `defaultValue` sets the initial value but the DOM takes over after that. You retrieve the final value through a ref or `new FormData(form)` inside `onSubmit`.

## A single onChange handler for multiple fields

When a form has several inputs, one handler per field works but creates boilerplate. The pattern is to store all field values in one object and use the input's `name` attribute as the key:

```jsx
function SignupForm() {
  const [form, setForm] = useState({ name: '', email: '', password: '' });

  function handleChange(e) {
    const { name, value } = e.target;
    setForm(prev => ({ ...prev, [name]: value }));
  }

  return (
    <form>
      <input name="name"     value={form.name}     onChange={handleChange} />
      <input name="email"    value={form.email}    onChange={handleChange} />
      <input name="password" value={form.password} onChange={handleChange} />
    </form>
  );
}
```

`[name]: value` is a computed property key — it uses the `name` string from the input as the key to update. One handler, any number of fields.

## Grouping form state in an object

Keeping form fields in a single state object has a cost: every field update replaces the whole object (via spread). For small forms this is fine. For large or deeply nested forms, consider splitting state into independent `useState` calls — each setter only re-renders components that consume that specific value.

```jsx
// Fine for most forms
const [form, setForm] = useState({ name: '', email: '' });

// Better when fields are independent and performance matters
const [name, setName]   = useState('');
const [email, setEmail] = useState('');
```

## Basic validation

Validation runs in `handleChange` (live feedback), `onBlur` (when the user leaves the field), or `onSubmit` (gate the network call). Showing errors immediately on every keystroke can feel aggressive; showing them only on blur strikes a better balance:

```jsx
const [errors, setErrors] = useState({});

function handleBlur(e) {
  const { name, value } = e.target;
  if (name === 'email' && !value.includes('@')) {
    setErrors(prev => ({ ...prev, email: 'Enter a valid email address.' }));
  } else {
    setErrors(prev => ({ ...prev, [name]: '' }));
  }
}
```

Disable the submit button until all required fields are valid to prevent premature submission:

```jsx
const isValid = form.name.trim() && form.email.includes('@') && form.password.length >= 8;

<button type="submit" disabled={!isValid}>
  Create account
</button>
```

## Submitting with onSubmit and e.preventDefault()

```jsx
function handleSubmit(e) {
  e.preventDefault();   // stop the browser navigating to "?"
  console.log('submitted:', form);
}

<form onSubmit={handleSubmit}>…</form>
```

`e.preventDefault()` prevents the browser from submitting the form as an HTTP GET/POST and navigating away. Always call it first, before any state updates or network calls.

<Callout type="tip">
**React 19 and Next.js Server Actions** — this chapter covers client-side controlled forms because understanding them is a prerequisite. In the Next.js chapter you will use `<form action={serverAction}>` instead: the `action` prop receives an async function that runs on the server, no `e.preventDefault()` needed and no `fetch` either. The `useActionState` and `useFormStatus` hooks give you pending/error feedback. We will revisit forms in the data-fetching lesson.

## Playground 2 — Signup form with inline validation

All fields share one `form` state object and one `handleChange` function. Errors appear on blur, not on every keystroke. The submit button stays disabled until all three fields pass their checks. Try submitting with an invalid email to see the error persist.

<Playground
  files={{
    '/App.js': `import { useState } from 'react';

function Field({ label, id, type = 'text', name, value, error, onChange, onBlur }) {
  return (
    <div style={{ marginBottom: '1rem' }}>
      <label
        htmlFor={id}
        style={{ display: 'block', fontWeight: 600, fontSize: '0.875rem', marginBottom: '0.25rem' }}
      >
        {label}
      </label>
      <input
        id={id}
        type={type}
        name={name}
        value={value}
        onChange={onChange}
        onBlur={onBlur}
        style={{
          width: '100%',
          padding: '0.5rem 0.75rem',
          border: \`1px solid \${error ? '#dc2626' : '#e2e8f0'}\`,
          borderRadius: '6px',
          fontSize: '0.875rem',
          fontFamily: 'sans-serif',
          outline: 'none',
          boxSizing: 'border-box',
        }}
      />
      {error && (
        <p style={{ margin: '0.25rem 0 0', fontSize: '0.75rem', color: '#dc2626' }}>{error}</p>
      )}
    </div>
  );
}

function validate(name, value) {
  if (name === 'name'     && !value.trim())           return 'Name is required.';
  if (name === 'email'    && !value.includes('@'))     return 'Enter a valid email address.';
  if (name === 'password' && value.length < 8)         return 'Password must be at least 8 characters.';
  return '';
}

export default function App() {
  const [form,   setForm]   = useState({ name: '', email: '', password: '' });
  const [errors, setErrors] = useState({ name: '', email: '', password: '' });
  const [submitted, setSubmitted] = useState(false);

  function handleChange(e) {
    const { name, value } = e.target;
    setForm(prev => ({ ...prev, [name]: value }));
    // Clear error as user types after it appeared
    if (errors[name]) {
      setErrors(prev => ({ ...prev, [name]: validate(name, value) }));
    }
  }

  function handleBlur(e) {
    const { name, value } = e.target;
    setErrors(prev => ({ ...prev, [name]: validate(name, value) }));
  }

  function handleSubmit(e) {
    e.preventDefault();
    const next = {
      name:     validate('name',     form.name),
      email:    validate('email',    form.email),
      password: validate('password', form.password),
    };
    setErrors(next);
    if (Object.values(next).every(v => !v)) {
      setSubmitted(true);
    }
  }

  const isValid =
    !validate('name',     form.name) &&
    !validate('email',    form.email) &&
    !validate('password', form.password);

  if (submitted) {
    return (
      <div style={{ fontFamily: 'sans-serif', padding: '2rem', maxWidth: '400px' }}>
        <p style={{ color: '#16a34a', fontWeight: 600 }}>✓ Account created for {form.email}</p>
      </div>
    );
  }

  return (
    <div style={{ fontFamily: 'sans-serif', padding: '2rem', maxWidth: '400px' }}>
      <h2 style={{ margin: '0 0 1.5rem', fontSize: '1.125rem', fontWeight: 700 }}>Create account</h2>
      <form onSubmit={handleSubmit} noValidate>
        <Field label="Name"     id="name"     name="name"     value={form.name}     error={errors.name}     onChange={handleChange} onBlur={handleBlur} />
        <Field label="Email"    id="email"    name="email"    type="email" value={form.email}    error={errors.email}    onChange={handleChange} onBlur={handleBlur} />
        <Field label="Password" id="password" name="password" type="password" value={form.password} error={errors.password} onChange={handleChange} onBlur={handleBlur} />
        <button
          type="submit"
          disabled={!isValid}
          style={{
            width: '100%',
            padding: '0.625rem',
            background: isValid ? 'rebeccapurple' : '#e2e8f0',
            color: isValid ? 'white' : '#94a3b8',
            border: 'none',
            borderRadius: '6px',
            fontWeight: 600,
            fontSize: '0.875rem',
            fontFamily: 'sans-serif',
            cursor: isValid ? 'pointer' : 'not-allowed',
          }}
        >
          Create account
        </button>
      </form>
    </div>
  );
}`,
  }}
  activeFile="/App.js"
  height={500}

## Playground 3 — Dynamic field-array form

The form state is an array of `{ id, value }` objects. "Add row" appends a new entry; the × button removes by id. Each input's `onChange` uses `map` to update the matching row immutably. Try adding five rows, editing them out of order, and removing the middle one.

## Controlled vs uncontrolled — when to choose each

<Callout type="tip">
**Controlled inputs** are the right default in React. React owns the value at all times, so you can:
- Validate on every keystroke or on blur
- Disable the submit button until valid
- Mirror the value to another part of the UI instantly
- Reset fields programmatically by setting state

**Uncontrolled inputs** (with `defaultValue` / `ref` / `FormData`) are worth considering when:
- You are integrating a non-React library that manages the DOM itself
- The form is very large and re-rendering every field on every keystroke is measurably slow
- You are migrating a legacy form and want a small diff

In Next.js, Server Actions accept a native `FormData` object — which works with both controlled and uncontrolled inputs. You will not always need to mirror every field into React state.
</Callout>
