# JSX & Rendering

JSX is a syntax extension for JavaScript. It lets you write markup that looks like HTML directly inside a `.js` file — no string concatenation, no template literals. Babel (or the Next.js compiler) transforms it into `React.createElement()` calls at build time.

## What JSX compiles to

This JSX:

```jsx
const el = <h1 className="title">Hello world</h1>;
```

Compiles to:

```js
const el = React.createElement('h1', { className: 'title' }, 'Hello world');
```

You never write that by hand — JSX exists so you don't have to.

## Expressions inside JSX

Wrap any JavaScript expression in `{}` to embed it inside markup:

```jsx
const name = 'Next Academy';
const el = <h1>Hello {name}</h1>;
// → <h1>Hello Next Academy</h1>
```

The expression inside `{}` must produce a value: a string, number, or another JSX element. Statements (loops, `if`) don't work — use ternaries or `&&` instead.

## Rules of JSX

1. **Return a single root element.** Wrap siblings in a `<div>` or the `<>` Fragment shorthand.
2. **Close every tag.** Self-closing tags need a slash: `<img />`, `<br />`.
3. **Use `className`, not `class`.** JSX maps to JavaScript objects — `class` is a reserved word.
4. **camelCase event handlers.** `onclick` → `onClick`, `onchange` → `onChange`.

## Key takeaway

JSX is syntactic sugar. Understanding what it compiles to helps you debug "expected expression" errors and understand why returning two elements without a wrapper fails.
