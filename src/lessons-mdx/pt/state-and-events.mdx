# Estado e Eventos

O estado é a forma como o React se lembra de coisas entre renders. Toda a UI interativa — um contador, um formulário, um toggle — é alimentada por estado.

## O que é o estado

Uma variável JavaScript normal reinicia em cada render. O React chama a tua função componente novamente sempre que precisa de atualizar o ecrã; qualquer declaração `let` começa do zero a cada vez:

```jsx
// ❌ Nunca funciona — count reinicia para 0 em cada render
function Counter() {
  let count = 0;
  return (
    <button onClick={() => { count += 1; console.log(count); }}>
      Count: {count}
    </button>
  );
}
```

O clique no botão dispara, `count` chega a 1, mas o ecrã nunca muda — o React não sabe que algo aconteceu. O estado é a solução: o React guarda-o *fora* da tua função e devolve o valor atual em cada render:

```jsx
import { useState } from 'react';

function Counter() {
  const [count, setCount] = useState(0);

  return (
    <button onClick={() => setCount(count + 1)}>
      Count: {count}
    </button>
  );
}
```

Chamar `setCount` diz ao React "volta a renderizar este componente". O React chama a tua função novamente — e desta vez devolve o novo valor de `count`.

## Declarar estado com useState

```jsx
const [valor, setValor] = useState(valorInicial);
```

- `valor` — o snapshot atual do estado para este render.
- `setValor` — chama isto para agendar um re-render com um novo valor.
- `valorInicial` — usado apenas no primeiro render; pode ser número, string, objeto, array ou `null`.

**Duas regras para hooks:**
- Chama `useState` (e todos os hooks) **ao nível de topo** do teu componente — nunca dentro de `if`, loops ou funções aninhadas.
- Chama hooks apenas dentro de componentes funcionais React ou hooks customizados.

O React identifica cada pedaço de estado pela ordem em que `useState` é chamado. Alterar essa ordem entre renders quebra a correspondência entre chamadas e valores guardados.

## As atualizações de estado são assíncronas

Chamar um setter não atualiza a variável imediatamente. O React agenda um re-render e o novo valor só é visível no *próximo* render. O valor do render atual é fixo — é uma constante:

```jsx
function Counter() {
  const [count, setCount] = useState(0);

  function handleClick() {
    setCount(count + 1);
    console.log(count); // ⚠️ Ainda é 0 — o render ainda não aconteceu
  }

  return <button onClick={handleClick}>Count: {count}</button>;
}
```

<Callout type="warn">
`console.log(count)` logo após `setCount` imprime sempre o **valor antigo**. `count` é uma constante vinculada no início deste render — nada a pode alterar a meio da função. O valor atualizado só aparece quando o React volta a renderizar e a tua função corre novamente.

Isto também significa que chamar `setCount(count + 1)` várias vezes no mesmo handler só incrementa uma vez — cada chamada lê o mesmo snapshot stale:

```jsx
// ❌ count começa em 0 — as três chamadas leem 0, o resultado é 1
setCount(count + 1);
setCount(count + 1);
setCount(count + 1);
```

Usa a forma de atualizador funcional para encadear múltiplas atualizações corretamente.
</Callout>

## A forma de atualizador funcional

Quando o próximo valor depende do anterior, passa uma função em vez de um valor:

```jsx
setCount(prev => prev + 1);
```

O React coloca estas funções em fila e aplica-as em ordem, cada uma recebendo o resultado da anterior:

```jsx
// ✅ Cada atualizador recebe o último prev — o resultado é 3
setCount(prev => prev + 1);
setCount(prev => prev + 1);
setCount(prev => prev + 1);
```

Usa a forma funcional sempre que:
- Chames o setter várias vezes num handler.
- O novo estado depender do estado atual.
- Estiveres dentro de um `setTimeout`, callback de `fetch`, ou qualquer função async onde o `valor` capturado possa estar desatualizado.

## Event handlers

O React passa um objeto de evento sintético a cada handler. Os padrões mais comuns:

```jsx
// onClick — dispara no clique
<button onClick={(e) => console.log(e.currentTarget)}>Clica</button>

// onChange — dispara em cada tecla pressionada
<input onChange={(e) => setText(e.target.value)} />

// onSubmit — dispara no envio do formulário
<form onSubmit={(e) => { e.preventDefault(); enviar(); }}>
  ...
</form>
```

**`e.preventDefault()`** impede a ação padrão do browser. Para formulários, impede a navegação da página; para links, impede seguir o href. Chama-o primeiro, antes de qualquer atualização de estado.

Define handlers como funções nomeadas quando a lógica ocupa mais de uma linha — mantém o JSX legível e torna a função fácil de testar:

```jsx
function handleChange(e) {
  const aparado = e.target.value.trimStart();
  setText(aparado);
}

return <input onChange={handleChange} />;
```

Passa a *referência* da função, não uma chamada: `onChange={handleChange}`, não `onChange={handleChange()}`. A segunda forma executa imediatamente em cada render.

## Nunca mutares diretamente o estado

O React deteta alterações por igualdade de referência. Mutar um objeto ou array existente não cria uma nova referência — o React vê o mesmo valor e ignora o re-render:

```jsx
// ❌ Mutação — o React vê o mesmo objeto, sem re-render
const next = state;
next.count += 1;
setState(next);

// ✅ Novo objeto — o React vê uma referência diferente, dispara re-render
setState({ ...state, count: state.count + 1 });
```

### Padrões de atualização imutável

**Objeto — atualizar um campo:**
```jsx
setState(prev => ({ ...prev, nome: 'Alice' }));
```

**Array — adicionar um item:**
```jsx
setItems(prev => [...prev, novoItem]);
```

**Array — remover um item:**
```jsx
setItems(prev => prev.filter(item => item.id !== idAlvo));
```

**Array — atualizar um item:**
```jsx
setItems(prev =>
  prev.map(item => item.id === idAlvo ? { ...item, feito: true } : item)
);
```

O padrão é sempre: espalha ou deriva um *novo* valor — nunca modifiques o que o React já tem.

## Conclusões principais

<Callout type="tip">
**O estado é memória fora da função.** Variáveis locais reiniciam em cada render; o estado persiste. O React guarda-o, o teu componente lê-o, e chamar o setter agenda o próximo render.

**As atualizações de estado são snapshots, não mutações.** Cada render captura o seu próprio valor de cada variável de estado. Chamar um setter agenda um re-render — o valor atual nunca muda a meio do render. `console.log(valor)` após um setter mostra sempre o snapshot antigo.

**Usa o atualizador funcional quando o novo estado depende do antigo.** `setX(prev => ...)` é a forma correta ao chamar o setter várias vezes num handler, em código assíncrono, ou sempre que não podes garantir que o valor capturado está atualizado.

**Nunca mutares objetos ou arrays em estado.** Produz sempre um novo valor: espalha objetos, espalha arrays para adicionar, `filter` para remover, `map` para atualizar. A mutação contorna a deteção de alterações do React e deixa a UI dessincronizada.

**`e.preventDefault()` primeiro.** Para submissões de formulários e cliques em links, chama-o antes de qualquer atualização de estado para parar a navegação padrão do browser.
</Callout>
