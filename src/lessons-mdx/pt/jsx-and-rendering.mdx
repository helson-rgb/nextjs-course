# JSX e Renderização

JSX é uma extensão de sintaxe que te permite escrever markup dentro de ficheiros JavaScript. Parece HTML — mas não é HTML. Sob o capô, cada expressão JSX compila para uma chamada `React.createElement()` simples antes de o browser executar o teu código.

## O que o JSX compila para

O compilador do Next.js transforma o teu JSX em tempo de build. Este JSX:

```jsx
const el = <h1 className="title">Hello world</h1>;
```

É identico em runtime a este JavaScript:

```js
const el = React.createElement('h1', { className: 'title' }, 'Hello world');
```

`React.createElement(type, props, ...children)` devolve um objeto JavaScript simples — um **elemento React** — que descreve o que deve aparecer no ecrã. Nunca o escreves à mão; o JSX é o atalho que o torna legível.

O aninhamento funciona da mesma forma:

```jsx
// O que escreves:
const card = (
  <div className="card">
    <h2>Título</h2>
    <p>Corpo.</p>
  </div>
);

// O que o compilador produz:
const card = React.createElement(
  'div',
  { className: 'card' },
  React.createElement('h2', null, 'Título'),
  React.createElement('p', null, 'Corpo.')
);
```

Cada nível de aninhamento torna-se uma chamada `React.createElement` aninhada. A árvore de objetos resultante é o **virtual DOM**.

## Expressões, atributos e fragments

### Incorporar expressões

Envolve qualquer **expressão** JavaScript em `{}` para a incorporar no markup:

```jsx
const user = { name: 'Alice', score: 42 };

return (
  <p>
    {user.name} marcou {user.score} pontos.
  </p>
);
```

O valor dentro de `{}` pode ser uma string, número, array ou qualquer expressão que produza um valor. **Statements** — `if`, `for`, `while` — não produzem valores. Usa um ternário ou `&&` em alternativa:

```jsx
// ternário: um ramo ou o outro
{isLoggedIn ? <Dashboard /> : <Login />}

// curto-circuito: renderiza apenas quando verdadeiro
{hasError && <ErrorBanner message={error.message} />}
```

### Diferenças nos atributos

Os atributos JSX seguem as regras de nomenclatura do JavaScript, não do HTML. As duas diferenças que encontrarás em todos os projetos:

| HTML | JSX | Razão |
|---|---|---|
| `class="btn"` | `className="btn"` | `class` é palavra reservada em JS |
| `for="email"` | `htmlFor="email"` | `for` é palavra reservada em JS |
| `<br>` | `<br />` | Todas as tags devem fechar |
| `<input>` | `<input />` | Todas as tags devem fechar |

Todos os outros atributos comuns — `id`, `href`, `src`, `style`, `aria-*`, `data-*` — têm a mesma ortografia que no HTML.

<Callout type="warn">
Passar `class` em vez de `className` não lança um erro no JSX — escreve silenciosamente o atributo errado no DOM, nenhum CSS é aplicado, e o bug pode ser invisível até abrires o DevTools. O Playground 2 abaixo vai mostrar-te isto em primeira mão.
</Callout>

### Tags self-closing

Em JSX, **todas as tags devem fechar** — seja com uma tag de fecho correspondente, ou com uma barra antes do `>`:

```jsx
<img src="/logo.svg" alt="Next Academy" />
<input type="email" name="email" />
<hr />
<br />
```

### Fragments e a regra de raiz única

Um componente só pode devolver **um elemento raiz**. Isto falha:

```jsx
// SyntaxError: Adjacent JSX elements must be wrapped in an enclosing tag.
return (
  <h1>Título</h1>
  <p>Subtítulo</p>
);
```

A solução óbvia é um `<div>` envolvente — mas isso adiciona um nó sem significado ao DOM e pode partir layouts (especialmente em tabelas e containers flex/grid). Os **Fragments** agrupam elementos sem adicionar nada ao DOM real:

```jsx
return (
  <>
    <h1>Título</h1>
    <p>Subtítulo</p>
  </>
);
```

`<>...</>` é atalho para `<React.Fragment>...</React.Fragment>`. Usa a forma nomeada quando precisares de passar uma prop `key` (por exemplo, dentro de um `.map()`):

```jsx
items.map((item) => (
  <React.Fragment key={item.id}>
    <dt>{item.term}</dt>
    <dd>{item.definition}</dd>
  </React.Fragment>
));
```

## De JSX a DOM real

Quando o teu componente devolve JSX, o React constrói um **virtual DOM** — uma árvore leve de objetos JavaScript simples que espelha a forma da UI que descreveste.

No primeiro render, o React converte esta árvore em nós DOM reais. Em cada render subsequente, faz **diff** da nova árvore virtual contra a anterior e aplica apenas o conjunto mínimo de alterações — um processo chamado **reconciliação**.

```
O teu JSX
  ↓ compilador
Chamadas React.createElement
  ↓ render
Árvore de objetos do virtual DOM
  ↓ diff de reconciliação
Patches mínimos no DOM real
```

Nunca chamas `document.createElement` diretamente. Descreves a UI que queres; o React descobre a sequência mais barata de operações DOM para a concretizar.

<Callout type="info">
O algoritmo completo de reconciliação — incluindo como o React decide quando reutilizar vs. destruir um nó DOM — é abordado na Lição 4, onde as props `key` estáveis se tornam críticas. Por agora o modelo mental é suficiente: o React mantém uma cópia rápida em memória e sincroniza o DOM real da forma mais eficiente possível.
</Callout>

## Conclusões principais

<Callout type="tip">
**JSX é açúcar sintático para `React.createElement`.** Cada expressão entre ângulos compila para uma chamada de função simples que devolve um objeto JavaScript. Perceber isto torna os erros JSX óbvios e o debugging direto.

**Três regras de atributos:** `className` não `class`, `htmlFor` não `for`, e todas as tags devem fechar com `/>` ou uma tag de fecho correspondente. Produzem falhas silenciosas — não erros — o que as torna fáceis de ignorar.

**Uma raiz, sempre — usa Fragments.** `<>...</>` agrupa irmãos sem adicionar nós DOM. É essencial em tabelas, listas e containers flex/grid onde um `<div>` extra quebra o layout.

**Tu descreves; o React decide.** O virtual DOM e o algoritmo de reconciliação aplicam apenas os patches DOM necessários. Nunca tocas no `document` diretamente — essa é a abstração que o JSX e o React te dão.
</Callout>
