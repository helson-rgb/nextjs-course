# JSX e Renderização

JSX é uma extensão de sintaxe para JavaScript. Permite escrever markup que parece HTML diretamente dentro de um ficheiro `.js` — sem concatenação de strings, sem template literals. O Babel (ou o compilador do Next.js) transforma-o em chamadas `React.createElement()` em tempo de build.

## O que o JSX compila para

Este JSX:

```jsx
const el = <h1 className="title">Hello world</h1>;
```

Compila para:

```js
const el = React.createElement('h1', { className: 'title' }, 'Hello world');
```

Nunca escreves isso à mão — o JSX existe para não teres de o fazer.

## Expressões dentro do JSX

Envolve qualquer expressão JavaScript em `{}` para a incorporar dentro do markup:

```jsx
const name = 'Next Academy';
const el = <h1>Hello {name}</h1>;
// → <h1>Hello Next Academy</h1>
```

A expressão dentro de `{}` tem de produzir um valor: uma string, número ou outro elemento JSX. Statements (loops, `if`) não funcionam — usa ternários ou `&&` em alternativa.

## Regras do JSX

1. **Devolve um único elemento raiz.** Envolve irmãos num `<div>` ou no atalho Fragment `<>`.
2. **Fecha todas as tags.** Tags self-closing precisam de uma barra: `<img />`, `<br />`.
3. **Usa `className`, não `class`.** O JSX mapeia para objetos JavaScript — `class` é uma palavra reservada.
4. **camelCase nos event handlers.** `onclick` → `onClick`, `onchange` → `onChange`.

## Conclusão principal

JSX é açúcar sintático. Perceber o que compila ajuda-te a depurar erros de "expected expression" e a entender porque é que devolver dois elementos sem um wrapper falha.
