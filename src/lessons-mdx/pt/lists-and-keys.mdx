# Renderização Condicional e Listas

Renderizar o conteúdo certo no momento certo é o núcleo de qualquer UI dinâmica. O React dá-te três ferramentas para output condicional e um padrão para arrays — tudo usando JavaScript simples sem sintaxe especial.

## Ternário: um ramo ou o outro

O operador ternário renderiza um de dois valores com base numa condição:

```jsx
{isLoggedIn ? <Dashboard /> : <LoginPrompt />}
```

Usa ternários quando ambos os ramos produzem output. Se o ramo falso não renderiza nada, `&&` é mais limpo.

Podes também usar ternários para alternar entre aspetos diferentes do mesmo elemento:

```jsx
<button className={isActive ? 'btn-primary' : 'btn-ghost'}>
  {isActive ? 'Ativo' : 'Inativo'}
</button>
```

Mantém os ternários em JSX curtos. Quando a condição ou qualquer ramo cresce para mais de uma linha, extrai-o para uma variável antes do return:

```jsx
const conteudo = isLoggedIn ? <Dashboard /> : <LoginPrompt />;

return <main>{conteudo}</main>;
```

## && curto-circuito: renderizar ou nada

Quando só queres renderizar algo no caso verdadeiro, faz curto-circuito com `&&`:

```jsx
{temErro && <BannerErro mensagem={erro.mensagem} />}
{isAdmin && <PainelAdmin />}
```

O React ignora `false`, `null` e `undefined` — não produzem nenhum output no DOM. `&&` funciona porque o JavaScript avalia `false && qualquerCoisa` como `false`, que o React ignora.

**A armadilha do 0.** O operando esquerdo deve ser um booleano, não um número. Se for `0`, o React renderiza o dígito "0":

```jsx
// ❌ Renderiza o string "0" quando o array está vazio
{items.length && <Lista items={items} />}

// ✅ Converte para booleano primeiro
{items.length > 0 && <Lista items={items} />}

// ✅ Ou usa um ternário com null
{items.length ? <Lista items={items} /> : null}
```

O mesmo se aplica a qualquer número falsy. Mantém o lado esquerdo como booleano estrito — `count > 0`, `Boolean(valor)`, ou dupla negação `!!valor`.

## Retorno antecipado: não renderizar nada

Um componente pode retornar `null` para não renderizar nenhum output. Isto é útil para guards — componentes que precisam de uma pré-condição para produzir qualquer output:

```jsx
function BannerSucesso({ mensagem }) {
  if (!mensagem) return null; // nada adicionado ao DOM

  return (
    <div className="banner banner--sucesso">
      {mensagem}
    </div>
  );
}
```

Retornar `null` não remove o componente da árvore React — os hooks continuam a correr, as subscrições continuam a disparar. Simplesmente não produz nós DOM. Usa-o quando o componente legitimamente não tem nada para mostrar, não como forma de ignorar efeitos secundários dispendiosos.

## Renderizar listas com .map()

Para renderizar um array, chama `.map()` e retorna JSX para cada item:

```jsx
const nomes = ['Alice', 'Bob', 'Carol'];

return (
  <ul>
    {nomes.map(nome => (
      <li key={nome}>{nome}</li>
    ))}
  </ul>
);
```

Cada item no callback de `.map()` pode ser tão complexo quanto precisares — um componente completo, múltiplos elementos num Fragment:

```jsx
{produtos.map(produto => (
  <React.Fragment key={produto.id}>
    <dt>{produto.nome}</dt>
    <dd>{produto.preco}</dd>
  </React.Fragment>
))}
```

A chamada `.map()` é apenas uma expressão JavaScript — vive dentro de `{}` em JSX da mesma forma que qualquer outra expressão.

## Porque cada item de lista precisa de uma key estável

O React usa keys para rastrear quais itens mudaram, foram adicionados ou removidos entre renders. Sem elas, o React recorre à comparação por posição — e isso causa bugs subtis difíceis de depurar.

```jsx
// ❌ Sem key — o React faz correspondência por posição
{items.map(item => <Row label={item.label} />)}

// ✅ Key estável — o React rastreia cada item pela sua identidade
{items.map(item => <Row key={item.id} label={item.label} />)}
```

### O bug do input que muda ao apagar

Aqui está o que corre mal sem keys estáveis. Três linhas com inputs não controlados, com key por índice:

```
Índice 0 → Alice  [input: ""]
Índice 1 → Bob    [input: "texto escrito"]   ← utilizador escreveu algo
Índice 2 → Carol  [input: ""]
```

Apaga o Bob. O React reconcilia o novo array `[Alice, Carol]` contra o antigo `[Alice, Bob, Carol]` **por posição**:

- Posição 0 → Alice: igual, mantém o nó DOM.
- Posição 1 → Carol: **era Bob** — o React reutiliza o nó DOM do Bob para a Carol. O nó DOM do input também é reutilizado, portanto "texto escrito" ainda está nele.
- Posição 2 → desapareceu.

A linha da Carol mostra agora o conteúdo escrito pelo Bob. O estado do DOM vazou.

Com `key={item.id}`:

- key `"alice"` → Alice: igual, mantido.
- key `"bob"` → desapareceu: **destruído com o seu nó DOM**, input limpo.
- key `"carol"` → Carol: igual, intocado.

O conteúdo correto fica na linha correta.

<Callout type="info">
**Quando o índice como key é seguro:** Se a lista for puramente estática — nunca reordenada, nunca com itens removidos do meio — e as linhas não tiverem estado interno (sem inputs, sem foco, sem animações), usar o índice do array como key é seguro. Exemplos: uma lista só de leitura de etiquetas, uma tabela de referência estática, uma lista paginada que substitui completamente ao mudar de página. O bug só aparece quando o React reutiliza um nó DOM que tem estado modificado pelo utilizador. Se nenhuma das tuas linhas tem estado interno, não há nada a vazar.
</Callout>

**Regras para keys:**

- **Únicas** entre irmãos na mesma lista (não globalmente).
- **Estáveis** — o mesmo item de dados deve receber a mesma key em todos os renders.
- **Não o índice do array** quando os items podem ser eliminados, adicionados ou reordenados.

Boas fontes de keys: IDs de base de dados, UUIDs, slugs, hashes de conteúdo estáveis. Se os teus dados não têm IDs, adiciona-os antes de os dados entrarem no estado — nunca os generates dentro de `.map()` com `Math.random()` ou `Date.now()`, pois uma nova key em cada render é equivalente a não ter key.

## Playground 2 — Bugs de keys lado a lado

Ambos os painéis renderizam a mesma lista e o mesmo componente `Row` (com um input não controlado). A única diferença é a key: índice à esquerda, ID estável à direita.

**Experiência:** escreve algo no input do Bob em *ambos* os painéis, depois clica × ao lado do Bob. No painel esquerdo, a linha da Carol mostra agora o texto do Bob — o estado do DOM vazou. No painel direito, a linha da Carol não foi afetada.

## Conclusões principais

<Callout type="tip">
**Três ferramentas para output condicional.** Ternário (`condição ? a : b`) quando ambos os ramos renderizam algo. `&&` quando só o ramo verdadeiro renderiza algo — mas mantém o lado esquerdo como booleano para evitar a armadilha do "0 renderiza como texto". Retorno antecipado `null` quando um componente não tem nada para mostrar.

**`.map()` é o único primitivo de lista.** Retorna JSX do callback; o array resultante entra em `{}` como qualquer outra expressão. Extrai o callback para uma função nomeada quando cresce para mais de duas ou três linhas.

**As keys são identidade, não ordem.** O React usa keys para fazer corresponder itens entre renders. Sem keys estáveis, o React reconcilia por posição — reutilizando nós DOM para os itens errados e vazando estado (como valores digitados em inputs) para as linhas erradas.

**Usa IDs de base de dados, slugs ou UUIDs como keys.** Nunca `Math.random()` ou `Date.now()` dentro de `.map()` — uma nova key em cada render destrói e recria o nó DOM em cada render. O índice do array só é seguro quando a lista é estática e as linhas não têm estado interno.
</Callout>
