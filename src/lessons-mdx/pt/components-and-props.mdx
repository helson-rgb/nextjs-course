# Componentes e Props

Uma aplicação React é uma **árvore de componentes**. Cada componente é uma função que aceita algum input (props) e devolve JSX a descrever um pedaço da UI. Os componentes compõem — assemblas peças pequenas e focadas em ecrãs maiores — e reutilizam livremente.

## Componentes funcionais

Um componente funcional é uma função JavaScript que:

- Aceita um único argumento `props` e devolve JSX.
- Tem um nome que **começa com letra maiúscula** (PascalCase).

```jsx
function Greeting() {
  return <p>Olá, mundo!</p>;
}

// Estilo arrow function — comportamento idêntico
const Greeting = () => <p>Olá, mundo!</p>;
```

A letra maiúscula é o que diz ao React "isto é um componente, não um elemento DOM". O React renderiza `<Greeting />` **chamando** `Greeting()`. O React renderiza `<div />` criando um nó DOM real.

```jsx
<Greeting />   // ✅ O React chama Greeting() — a tua função executa
<greeting />   // ❌ O React cria um elemento DOM <greeting> — a tua função nunca é chamada
```

Convenção: um componente por ficheiro, o nome do ficheiro corresponde ao nome do componente. `Button.jsx` exporta `function Button`.

## Props

Props são os dados que um pai passa para um filho. Fluem **num único sentido** — pai para filho — e são **só de leitura**: um componente lê as suas props mas nunca escreve de volta.

### Passar e ler props

```jsx
// O pai passa props como atributos
<UserCard name="Alice" role="Admin" />

// O filho recebe um único objeto props
function UserCard(props) {
  return (
    <div>
      <strong>{props.name}</strong>
      <span>{props.role}</span>
    </div>
  );
}
```

### Desestruturação e valores por defeito

Desestrutura as props ao nível do parâmetro para tornar a intenção clara e define props opcionais inline:

```jsx
function UserCard({ name, role = 'Membro', avatar = '/avatar-padrao.png' }) {
  return (
    <div>
      <img src={avatar} alt={name} />
      <strong>{name}</strong>
      <span>{role}</span>
    </div>
  );
}
```

`role = 'Membro'` significa que o chamador pode omitir `role` completamente e o componente fará fallback graciosamente.

### A prop children

Qualquer JSX colocado **entre a tag de abertura e fecho** de um componente chega como a prop especial `children`. Este é o primitivo que torna a composição possível:

```jsx
function Card({ children }) {
  return (
    <div style={{ border: '1px solid #e2e8f0', borderRadius: '8px', padding: '1rem' }}>
      {children}
    </div>
  );
}

// O chamador controla o que vai dentro
<Card>
  <h2>Lição 1</h2>
  <p>Aprende como o JSX funciona.</p>
  <Button>Iniciar</Button>
</Card>
```

`children` é apenas uma prop normal. O seu tipo é `React.ReactNode`: texto, um único elemento, um array ou `null` funcionam todos.

### Documentar props com JSDoc

O React não tem validação de props em runtime incorporada. A alternativa moderna e leve é um comentário JSDoc — o teu editor usa-o para autocomplete e documentação inline:

```jsx
/**
 * @param {{
 *   variant?: 'primary' | 'secondary' | 'ghost';
 *   disabled?: boolean;
 *   children: React.ReactNode;
 * }} props
 */
function Button({ variant = 'primary', disabled = false, children }) {
  // ...
}
```

Num projeto TypeScript usarias uma `interface Props` em vez disso. JSDoc é o equivalente sem dependências para ficheiros JavaScript simples.

## Composição em vez de configuração

Quando um componente precisa de ser flexível, o instinto é adicionar mais props:

```jsx
// ❌ Explosão de props de configuração — uma flag por funcionalidade
<Card
  title="Lição 1"
  badge="12 min"
  ctaLabel="Iniciar"
  showDivider
  collapsible
  badgeColor="blue"
/>
```

Cada requisito adiciona outra prop. O componente torna-se uma mini DSL em vez de um primitivo de UI. A alternativa é **composição**: deixa o chamador passar conteúdo estruturado como `children` e slots nomeados:

```jsx
// ✅ Composição — o chamador monta a estrutura
<Card header="Lição 1">
  <p>JSX e Renderização — 12 min</p>
  <Button>Iniciar</Button>
</Card>
```

A regra de ouro: se te encontras a adicionar props que controlam **o que** é renderizado (flags booleanas, strings de label, nomes de cor), considera transformar esse conteúdo num slot `children` em vez disso.

## Os componentes devem ser puros

Um componente é **puro** se devolve sempre o mesmo JSX para as mesmas props, sem efeitos secundários durante a fase de render:

```jsx
// ✅ Puro — mesmas props, mesmo output, sempre
function Greeting({ name }) {
  return <p>Olá, {name}!</p>;
}

// ❌ Impuro — muta uma variável externa durante o render
let callCount = 0;
function Counter() {
  callCount += 1; // efeito secundário durante o render
  return <p>Renderizado {callCount} vezes</p>;
}
```

**Durante o render**: sem mutações, sem pedidos de rede, sem leitura de `localStorage`, sem `setTimeout`. Os efeitos secundários pertencem a event handlers ou ao hook `useEffect` — abordado na Lição 6.

<Callout type="info">
O Strict Mode do React chama intencionalmente a tua função componente duas vezes em desenvolvimento para expor comportamento impuro. Se a tua UI duplicar ou os logs dispararem duas vezes, é o Strict Mode a funcionar corretamente — não é um bug.
</Callout>

## Erros comuns

<Callout type="warn">
**Esquecer o PascalCase.** Escrever `<userCard />` diz ao React para criar um elemento DOM `<usercard>` — a tua função componente nunca é chamada. O erro resultante ("Unknown prop on `<usercard>`") é confuso porque parece um problema de JSX, não de nomenclatura. Capitaliza sempre.

**Mutar props.** As props são só de leitura. `props.count++` ou `item.name = 'novo'` dentro de um componente corrompe silenciosamente os dados do pai. Se precisares de uma versão modificada, cria uma cópia local: `const atualizado = { ...props, count: props.count + 1 }`.

**Passar object literals inline.** `<Comp style={{ color: 'red' }} />` cria um objeto completamente novo em cada render. Se `Comp` compara referências de props (via `React.memo` ou similar), verá sempre uma prop alterada e re-renderizará desnecessariamente. Define objetos estáticos fora do componente, ou calcula-os com `useMemo` quando dependem de estado.
</Callout>

## Conclusões principais

<Callout type="tip">
**Os componentes são funções puras.** Mesmas props, mesmo JSX — sempre. Sem efeitos secundários durante o render. A pureza torna os componentes previsíveis, testáveis e seguros para o React chamar múltiplas vezes.

**Desestrutura as props e define os padrões ao nível do parâmetro.** `function Card({ header = 'Sem título', children })` é mais limpo e seguro do que verificar dentro do corpo.

**`children` é o primitivo de composição.** Tudo o que está entre a tag de abertura e fecho chega como `children`. Usa-o em vez de adicionar mais props de configuração — mantém os componentes focados e os chamadores no controlo.

**Prefere composição em vez de configuração.** Quando as props começam a controlar o que é renderizado (flags, strings de label, nomes de cor), extrai esse conteúdo para um slot `children`. Menos props, mais flexibilidade.
</Callout>
