# Rendering Condizionale e Liste

Renderizzare il contenuto giusto al momento giusto è il nucleo di qualsiasi UI dinamica. React ti fornisce tre strumenti per l'output condizionale e un pattern per gli array — tutti usando JavaScript semplice senza sintassi speciale.

## Ternario: un ramo o l'altro

L'operatore ternario renderizza uno di due valori in base a una condizione:

```jsx
{isLoggedIn ? <Dashboard /> : <LoginPrompt />}
```

Usa i ternari quando entrambi i rami producono output. Se il ramo falso non renderizza nulla, `&&` è più pulito.

Puoi anche usare i ternari per alternare tra aspetti diversi dello stesso elemento:

```jsx
<button className={isActive ? 'btn-primary' : 'btn-ghost'}>
  {isActive ? 'Attivo' : 'Inattivo'}
</button>
```

Mantieni i ternari in JSX brevi. Quando la condizione o uno dei rami cresce oltre una riga, estrailo in una variabile prima del return:

```jsx
const contenuto = isLoggedIn ? <Dashboard /> : <LoginPrompt />;

return <main>{contenuto}</main>;
```

## && short-circuit: renderizza o nulla

Quando vuoi renderizzare qualcosa solo nel caso vero, usa lo short-circuit con `&&`:

```jsx
{haError && <BannerErrore messaggio={errore.messaggio} />}
{isAdmin && <PannelloAdmin />}
```

React ignora `false`, `null` e `undefined` — non producono alcun output nel DOM. `&&` funziona perché JavaScript valuta `false && qualcosa` come `false`, che React salta.

**La trappola dello 0.** L'operando sinistro deve essere un booleano, non un numero. Se è `0`, React renderizza la cifra "0":

```jsx
// ❌ Renderizza la stringa "0" quando l'array è vuoto
{items.length && <Lista items={items} />}

// ✅ Converti prima in booleano
{items.length > 0 && <Lista items={items} />}

// ✅ Oppure usa un ternario con null
{items.length ? <Lista items={items} /> : null}
```

Lo stesso vale per qualsiasi numero falsy. Mantieni il lato sinistro come booleano stretto — `count > 0`, `Boolean(valore)`, o doppia negazione `!!valore`.

## Return anticipato: non renderizzare nulla

Un componente può restituire `null` per rinunciare al rendering. È utile per i guard — componenti che necessitano di una precondizione per produrre qualsiasi output:

```jsx
function BannerSuccesso({ messaggio }) {
  if (!messaggio) return null; // nulla aggiunto al DOM

  return (
    <div className="banner banner--successo">
      {messaggio}
    </div>
  );
}
```

Restituire `null` non rimuove il componente dall'albero React — gli hook continuano a girare, le subscription continuano a scattare. Produce semplicemente nessun nodo DOM. Usalo quando il componente non ha legittimamente nulla da mostrare, non come modo per saltare effetti collaterali costosi.

## Renderizzare liste con .map()

Per renderizzare un array, chiama `.map()` e restituisci JSX per ogni elemento:

```jsx
const nomi = ['Alice', 'Bob', 'Carol'];

return (
  <ul>
    {nomi.map(nome => (
      <li key={nome}>{nome}</li>
    ))}
  </ul>
);
```

Ogni elemento nel callback di `.map()` può essere complesso quanto necessario — un componente completo, più elementi in un Fragment:

```jsx
{prodotti.map(prodotto => (
  <React.Fragment key={prodotto.id}>
    <dt>{prodotto.nome}</dt>
    <dd>{prodotto.prezzo}</dd>
  </React.Fragment>
))}
```

La chiamata `.map()` è semplicemente un'espressione JavaScript — vive dentro `{}` in JSX come qualsiasi altra espressione.

## Perché ogni elemento di lista necessita di una key stabile

React usa le key per tracciare quali elementi sono cambiati, sono stati aggiunti o rimossi tra i render. Senza di esse, React ricade sul confronto per posizione — e questo causa bug sottili difficili da debuggare.

```jsx
// ❌ Nessuna key — React fa corrispondenza per posizione
{items.map(item => <Row label={item.label} />)}

// ✅ Key stabile — React traccia ogni elemento per identità
{items.map(item => <Row key={item.id} label={item.label} />)}
```

### Il bug dell'input che si sposta eliminando un elemento

Ecco cosa va storto senza key stabili. Tre righe con input non controllati, con key per indice:

```
Indice 0 → Alice  [input: ""]
Indice 1 → Bob    [input: "testo digitato"]   ← l'utente ha scritto qualcosa
Indice 2 → Carol  [input: ""]
```

Elimini Bob. React riconcilia il nuovo array `[Alice, Carol]` con il vecchio `[Alice, Bob, Carol]` **per posizione**:

- Posizione 0 → Alice: uguale, mantieni il nodo DOM.
- Posizione 1 → Carol: **era Bob** — React riusa il nodo DOM di Bob per Carol. Anche il nodo DOM dell'input viene riusato, quindi "testo digitato" è ancora lì.
- Posizione 2 → sparita.

La riga di Carol mostra ora il contenuto digitato da Bob. Lo stato del DOM è trapelato.

Con `key={item.id}`:

- key `"alice"` → Alice: uguale, mantenuta.
- key `"bob"` → sparita: **distrutta con il suo nodo DOM**, input pulito.
- key `"carol"` → Carol: uguale, intatta.

Il contenuto corretto rimane nella riga corretta.

<Callout type="info">
**Quando l'indice come key è sicuro:** Se la lista è puramente statica — mai riordinata, mai con elementi rimossi dal mezzo — e le righe non hanno stato interno (nessun input, nessun focus, nessuna animazione), usare l'indice dell'array come key è sicuro. Esempi: una lista di sola lettura di etichette, una tabella di riferimento statica, una lista paginata che si sostituisce completamente al cambio pagina. Il bug emerge solo quando React riusa un nodo DOM che contiene stato modificato dall'utente. Se nessuna delle tue righe ha stato interno, non c'è nulla che possa trapelare.
</Callout>

**Regole per le key:**

- **Uniche** tra i fratelli nella stessa lista (non globalmente).
- **Stabili** — lo stesso elemento di dati deve ricevere la stessa key ad ogni render.
- **Non l'indice dell'array** quando gli elementi possono essere eliminati, aggiunti o riordinati.

Buone fonti di key: ID di database, UUID, slug, hash di contenuto stabili. Se i tuoi dati non hanno ID, aggiungili prima che entrino nello stato — non generarli mai dentro `.map()` con `Math.random()` o `Date.now()`, poiché una nuova key ad ogni render è equivalente a non avere key.

## Playground 2 — Bug delle key a confronto

Entrambi i pannelli renderizzano la stessa lista e lo stesso componente `Row` (con un input non controllato). L'unica differenza è la key: indice a sinistra, ID stabile a destra.

**Esperimento:** digita qualcosa nell'input di Bob in *entrambi* i pannelli, poi clicca × accanto a Bob. Nel pannello sinistro la riga di Carol mostra ora il testo di Bob — lo stato del DOM è trapelato. Nel pannello destro la riga di Carol è intatta.

<Playground

    '/App.js': `import { useState } from 'react';

  { id: 'alice', label: 'Alice' },
  { id: 'bob',   label: 'Bob'   },
  { id: 'carol', label: 'Carol' },

  return (

        defaultValue={label}
        style={{

## Playground 3 — Filtro / ricerca

`results` viene derivato da `UTENTI` e `query` ad ogni render — non serve stato separato per la lista filtrata. Poiché `results` è sempre sincronizzato con entrambi, il `&&` / ternario per lo stato vuoto funziona automaticamente. Prova ad aggiungere un filtro per ruolo (un secondo input o un insieme di bottoni toggle) accanto alla ricerca per nome.

## Punti chiave

<Callout type="tip">
**Tre strumenti per l'output condizionale.** Ternario (`condizione ? a : b`) quando entrambi i rami renderizzano qualcosa. `&&` quando solo il ramo vero renderizza qualcosa — ma mantieni il lato sinistro come booleano per evitare la trappola dello "0 che si renderizza come testo". Return anticipato `null` quando un componente non ha nulla da mostrare.

**`.map()` è l'unico primitivo per le liste.** Restituisci JSX dal callback; l'array risultante entra in `{}` come qualsiasi altra espressione. Estrai il callback in una funzione con nome quando cresce oltre due o tre righe.

**Le key sono identità, non ordine.** React usa le key per abbinare gli elementi tra i render. Senza key stabili, React riconcilia per posizione — riusando nodi DOM per gli elementi sbagliati e facendo trapelare stato (come valori digitati negli input) nelle righe sbagliate.

**Usa ID di database, slug o UUID come key.** Mai `Math.random()` o `Date.now()` dentro `.map()` — una nuova key ad ogni render distrugge e ricrea il nodo DOM ad ogni render. L'indice dell'array è sicuro solo quando la lista è statica e le righe non hanno stato interno.
</Callout>
