# Componenti e Props

Un'applicazione React è un **albero di componenti**. Ogni componente è una funzione che accetta un input (props) e restituisce JSX che descrive un pezzo di UI. I componenti si compongono — assembli pezzi piccoli e focalizzati in schermate più grandi — e si riutilizzano liberamente.

## Componenti funzionali

Un componente funzionale è una funzione JavaScript che:

- Accetta un singolo argomento `props` e restituisce JSX.
- Ha un nome che **inizia con una lettera maiuscola** (PascalCase).

```jsx
function Greeting() {
  return <p>Ciao, mondo!</p>;
}

// Stile arrow function — comportamento identico
const Greeting = () => <p>Ciao, mondo!</p>;
```

La lettera maiuscola è ciò che dice a React "questo è un componente, non un elemento DOM". React renderizza `<Greeting />` **chiamando** `Greeting()`. React renderizza `<div />` creando un nodo DOM reale.

```jsx
<Greeting />   // ✅ React chiama Greeting() — la tua funzione viene eseguita
<greeting />   // ❌ React crea un elemento DOM <greeting> — la tua funzione non viene mai chiamata
```

Convenzione: un componente per file, il nome del file corrisponde al nome del componente. `Button.jsx` esporta `function Button`.

## Props

Le props sono i dati che un genitore passa a un figlio. Scorrono **in un unico senso** — genitore verso figlio — e sono **di sola lettura**: un componente legge le sue props ma non scrive mai indietro.

### Passare e leggere le props

```jsx
// Il genitore passa le props come attributi
<UserCard name="Alice" role="Admin" />

// Il figlio riceve un unico oggetto props
function UserCard(props) {
  return (
    <div>
      <strong>{props.name}</strong>
      <span>{props.role}</span>
    </div>
  );
}
```

### Destrutturazione e valori predefiniti

Destruttura le props a livello del parametro per rendere chiara l'intenzione e imposta props opzionali inline:

```jsx
function UserCard({ name, role = 'Membro', avatar = '/avatar-default.png' }) {
  return (
    <div>
      <img src={avatar} alt={name} />
      <strong>{name}</strong>
      <span>{role}</span>
    </div>
  );
}
```

`role = 'Membro'` significa che il chiamante può omettere `role` completamente e il componente ricadrà in modo elegante sul valore predefinito.

### La prop children

Qualsiasi JSX posizionato **tra il tag di apertura e di chiusura** di un componente arriva come prop speciale `children`. Questo è il primitivo che rende possibile la composizione:

```jsx
function Card({ children }) {
  return (
    <div style={{ border: '1px solid #e2e8f0', borderRadius: '8px', padding: '1rem' }}>
      {children}
    </div>
  );
}

// Il chiamante controlla cosa va dentro
<Card>
  <h2>Lezione 1</h2>
  <p>Impara come funziona JSX.</p>
  <Button>Inizia</Button>
</Card>
```

`children` è semplicemente una prop normale. Il suo tipo è `React.ReactNode`: testo, un singolo elemento, un array o `null` funzionano tutti.

### Documentare le props con JSDoc

React non ha una validazione delle props in runtime incorporata. L'alternativa moderna e leggera è un commento JSDoc — il tuo editor lo usa per l'autocompletamento e la documentazione inline:

```jsx
/**
 * @param {{
 *   variant?: 'primary' | 'secondary' | 'ghost';
 *   disabled?: boolean;
 *   children: React.ReactNode;
 * }} props
 */
function Button({ variant = 'primary', disabled = false, children }) {
  // ...
}
```

In un progetto TypeScript useresti un'`interface Props` al suo posto. JSDoc è l'equivalente senza dipendenze per i file JavaScript semplici.

## Composizione invece di configurazione

Quando un componente deve essere flessibile, l'istinto è aggiungere più props:

```jsx
// ❌ Esplosione di props di configurazione — un flag per funzionalità
<Card
  title="Lezione 1"
  badge="12 min"
  ctaLabel="Inizia"
  showDivider
  collapsible
  badgeColor="blue"
/>
```

Ogni requisito aggiunge un'altra prop. Il componente diventa una mini DSL invece di un primitivo UI. L'alternativa è la **composizione**: lascia che il chiamante passi contenuto strutturato come `children` e slot nominati:

```jsx
// ✅ Composizione — il chiamante assembla la struttura
<Card header="Lezione 1">
  <p>JSX & Rendering — 12 min</p>
  <Button>Inizia</Button>
</Card>
```

La regola d'oro: se ti ritrovi ad aggiungere props che controllano **cosa** viene renderizzato (flag booleane, stringhe di etichette, nomi di colori), considera di trasformare quel contenuto in uno slot `children`.

## I componenti devono essere puri

Un componente è **puro** se restituisce sempre lo stesso JSX per le stesse props, senza effetti collaterali durante la fase di render:

```jsx
// ✅ Puro — stesse props, stesso output, sempre
function Greeting({ name }) {
  return <p>Ciao, {name}!</p>;
}

// ❌ Impuro — muta una variabile esterna durante il render
let callCount = 0;
function Counter() {
  callCount += 1; // effetto collaterale durante il render
  return <p>Renderizzato {callCount} volte</p>;
}
```

**Durante il render**: nessuna mutazione, nessuna richiesta di rete, nessuna lettura da `localStorage`, nessun `setTimeout`. Gli effetti collaterali appartengono ai gestori di eventi o all'hook `useEffect` — trattato nella Lezione 6.

<Callout type="info">
Lo Strict Mode di React chiama intenzionalmente la tua funzione componente due volte in sviluppo per esporre comportamenti impuri. Se la tua UI si duplica o i log vengono sparati due volte, è lo Strict Mode che funziona correttamente — non è un bug.
</Callout>

## Errori comuni

<Callout type="warn">
**Dimenticare il PascalCase.** Scrivere `<userCard />` dice a React di creare un elemento DOM `<usercard>` — la tua funzione componente non viene mai chiamata. L'errore risultante ("Unknown prop on `<usercard>`") è confuso perché sembra un problema JSX, non di denominazione. Usa sempre la maiuscola.

**Mutare le props.** Le props sono di sola lettura. `props.count++` o `item.name = 'nuovo'` all'interno di un componente corrompe silenziosamente i dati del genitore. Se hai bisogno di una versione modificata, crea una copia locale: `const aggiornato = { ...props, count: props.count + 1 }`.

**Passare oggetti letterali inline.** `<Comp style={{ color: 'red' }} />` crea un oggetto completamente nuovo ad ogni render. Se `Comp` confronta i riferimenti delle props (tramite `React.memo` o simili), vedrà sempre una prop cambiata e ri-renderizzerà inutilmente. Definisci gli oggetti statici fuori dal componente, o calcolali con `useMemo` quando dipendono dallo stato.
</Callout>

## Punti chiave

<Callout type="tip">
**I componenti sono funzioni pure.** Stesse props in entrata, stesso JSX in uscita — sempre. Nessun effetto collaterale durante il render. La purezza rende i componenti prevedibili, testabili e sicuri da chiamare più volte per React.

**Destruttura le props e imposta i valori predefiniti a livello del parametro.** `function Card({ header = 'Senza titolo', children })` è più pulito e sicuro che verificare all'interno del corpo.

**`children` è il primitivo di composizione.** Tutto ciò che si trova tra il tag di apertura e quello di chiusura arriva come `children`. Usalo invece di aggiungere più props di configurazione — mantiene i componenti focalizzati e i chiamanti in controllo.

**Preferisci la composizione alla configurazione.** Quando le props iniziano a controllare cosa viene renderizzato (flag, stringhe di etichette, nomi di colori), estrai quel contenuto in uno slot `children`. Meno props, più flessibilità.
</Callout>
