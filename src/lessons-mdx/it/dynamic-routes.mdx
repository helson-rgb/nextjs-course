# Route Dinamiche

La maggior parte delle route in un'applicazione reale non è nota al momento della scrittura del codice — slug di blog, ID prodotto, profili utente. I segmenti di route dinamici ti permettono di definire un singolo file che gestisce un insieme infinito di URL. Next.js popola il segmento al momento della richiesta (o al momento del build con `generateStaticParams`).

## La convenzione di cartella `[param]`

Racchiudi il nome di una cartella tra parentesi quadre per renderla dinamica:

```
app/
└── blog/
    ├── page.js          ← /blog
    └── [slug]/
        └── page.js      ← /blog/qualsiasi-cosa, /blog/hello-world, /blog/42
```

Il nome del segmento all'interno delle parentesi diventa una chiave sull'oggetto `params`. In Next.js 16, `params` è una **Promise** — usa sempre `await` prima di leggerne i valori:

```jsx
// app/blog/[slug]/page.js
export default async function BlogPost({ params }) {
  const { slug } = await params   // ← obbligatorio usare await in Next.js 16
  return <h1>{slug}</h1>
}
```

In un Client Component, usa `use()` di React per estrarre il valore dalla promise:

```jsx
'use client'
import { use } from 'react'

export default function BlogPost({ params }) {
  const { slug } = use(params)
  return <h1>{slug}</h1>
}
```

## Segmenti dinamici multipli

Annida cartelle dinamiche per route con più di una parte variabile:

```
app/shop/[category]/[product]/page.js
```

| URL | `params` |
|---|---|
| `/shop/shoes/air-max` | `{ category: 'shoes', product: 'air-max' }` |
| `/shop/bags/tote-01` | `{ category: 'bags', product: 'tote-01' }` |

```jsx
export default async function ProductPage({ params }) {
  const { category, product } = await params
  // ...
}
```

## `notFound()` — gestire i params sconosciuti

Quando il valore di un param non corrisponde a dati reali, chiama `notFound()` da `next/navigation`. Next.js renderizza il `not-found.js` più vicino e restituisce un 404:

```jsx
import { notFound } from 'next/navigation'

const POSTS = {
  'hello-world': { title: 'Hello World', body: '...' },
  'next-js-tips': { title: 'Next.js Tips', body: '...' },
}

export default async function BlogPost({ params }) {
  const { slug } = await params
  const post = POSTS[slug]
  if (!post) notFound()    // 404 per qualsiasi slug sconosciuto
  return <article>{post.title}</article>
}
```

## `generateStaticParams` — pre-rendering al momento del build

Per impostazione predefinita, una route dinamica viene renderizzata su richiesta — il server risolve `params` quando la richiesta arriva. Esporta `generateStaticParams` per indicare a Next.js quali valori di param pre-renderizzare come HTML statico durante `next build`:

```jsx
// app/blog/[slug]/page.js
export async function generateStaticParams() {
  const posts = await fetch('https://api.example.com/posts').then(r => r.json())

  return posts.map(post => ({ slug: post.slug }))
  // es. [{ slug: 'hello-world' }, { slug: 'next-js-tips' }, ...]
}

export default async function BlogPost({ params }) {
  const { slug } = await params
  // ...
}
```

Next.js chiama `generateStaticParams` una volta durante il build, genera un file HTML per ogni slug restituito e serve quei file direttamente dalla CDN — nessuna elaborazione server al momento della richiesta.

### `generateStaticParams` con deduplicazione di `fetch`

Se `generateStaticParams` e il componente di pagina chiamano entrambi la stessa URL di `fetch`, Next.js deduplica la richiesta di rete. I dati vengono recuperati una volta sola e condivisi tra entrambe le funzioni.

### `dynamicParams` — 404 per slug non elencati

Per impostazione predefinita, gli slug non restituiti da `generateStaticParams` vengono renderizzati su richiesta (con fallback al server). Imposta `dynamicParams = false` per restituire invece un 404:

```jsx
export const dynamicParams = false   // slug sconosciuti → 404

export async function generateStaticParams() {
  return [{ slug: 'hello-world' }, { slug: 'next-js-tips' }]
}
```

## Segmenti catch-all — `[...slug]`

Aggiungi `...` all'interno delle parentesi per corrispondere a qualsiasi numero di segmenti di percorso:

```
app/docs/[...slug]/page.js
```

| URL | `params.slug` |
|---|---|
| `/docs/intro` | `['intro']` |
| `/docs/api/hooks` | `['api', 'hooks']` |
| `/docs/api/hooks/useEffect` | `['api', 'hooks', 'useEffect']` |

```jsx
export default async function DocsPage({ params }) {
  const { slug } = await params  // slug è un string[]
  const path = slug.join('/')    // 'api/hooks'
  // ...
}
```

`/docs` stesso (senza slug) restituisce 404 con un catch-all. Usa un catch-all **opzionale** se vuoi corrispondere anche al percorso padre.

## Catch-all opzionale — `[[...slug]]`

Le doppie parentesi rendono l'intero segmento opzionale:

```
app/docs/[[...slug]]/page.js
```

| URL | `params.slug` |
|---|---|
| `/docs` | `undefined` |
| `/docs/intro` | `['intro']` |
| `/docs/api/hooks` | `['api', 'hooks']` |

```jsx
export default async function DocsPage({ params }) {
  const { slug } = await params
  if (!slug) return <DocsHome />           // /docs
  return <DocPage path={slug.join('/')} /> // /docs/qualsiasi-cosa
}
```

## L'app del corso — due route dinamiche

Questo corso usa `[slug]` e `[id]` in due punti:

**`src/app/lessons/[slug]/page.js`** — tutte le 17 lezioni sono pre-renderizzate al momento del build. `generateStaticParams` restituisce una voce `{ slug }` per ogni lezione nel registro. Gli slug sconosciuti ricadono su `notFound()`.

```jsx
// src/app/lessons/[slug]/page.js (semplificato)
export async function generateStaticParams() {
  return getAllLessons().map(lesson => ({ slug: lesson.slug }))
}

export default async function LessonPage({ params }) {
  const { slug } = await params
  const lesson = getLessonBySlug(slug)
  if (!lesson) notFound()
  // ...
}
```

**`src/app/playground/posts/[id]/page.js`** — recupera dati da `jsonplaceholder.typicode.com` su richiesta. Nessun `generateStaticParams` — ogni ID post viene risolto lato server al momento della richiesta.

## Punti chiave

<Callout type="tip">
**`params` è una Promise in Next.js 16.** Usa sempre `await params` nei Server Component prima di destrutturare. Nei Client Component, usa `use(params)` di React.

**`generateStaticParams` sposta il rendering al momento del build.** Restituisci un array di oggetti param e Next.js pre-renderizza un file HTML statico per ciascuno. Gli slug sconosciuti vengono gestiti su richiesta a meno che non imposti `dynamicParams = false`.

**`notFound()` renderizza il `not-found.js` più vicino.** Chiamalo quando il valore di un param non corrisponde a dati reali — dopo che un fetch con await restituisce null, o dopo che una ricerca in una mappa locale fallisce.

**Il catch-all `[...slug]` corrisponde a più segmenti come array.** L'opzionale `[[...slug]]` corrisponde anche al percorso padre (dove `slug` è `undefined`).

**Le richieste `fetch` di `generateStaticParams` sono deduplicate.** Se il componente di pagina chiama la stessa URL, Next.js effettua una sola richiesta di rete durante il build.
</Callout>
