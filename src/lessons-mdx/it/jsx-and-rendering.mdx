# JSX e Rendering

JSX è un'estensione sintattica che ti permette di scrivere markup all'interno di file JavaScript. Sembra HTML — ma non è HTML. Sotto il cofano, ogni espressione JSX viene compilata in una semplice chiamata `React.createElement()` prima che il browser esegua il codice.

## Cosa compila JSX

Il compilatore di Next.js trasforma il tuo JSX in fase di build. Questo JSX:

```jsx
const el = <h1 className="title">Hello world</h1>;
```

È identico a runtime a questo JavaScript:

```js
const el = React.createElement('h1', { className: 'title' }, 'Hello world');
```

`React.createElement(type, props, ...children)` restituisce un semplice oggetto JavaScript — un **elemento React** — che descrive cosa deve apparire sullo schermo. Non lo scrivi mai a mano; JSX è la scorciatoia che lo rende leggibile.

L'annidamento funziona allo stesso modo:

```jsx
// Cosa scrivi:
const card = (
  <div className="card">
    <h2>Titolo</h2>
    <p>Corpo.</p>
  </div>
);

// Cosa produce il compilatore:
const card = React.createElement(
  'div',
  { className: 'card' },
  React.createElement('h2', null, 'Titolo'),
  React.createElement('p', null, 'Corpo.')
);
```

Ogni livello di annidamento diventa una chiamata `React.createElement` annidata. L'albero di oggetti risultante è il **virtual DOM**.

## Espressioni, attributi e fragment

### Incorporare espressioni

Racchiudi qualsiasi **espressione** JavaScript in `{}` per incorporarla nel markup:

```jsx
const user = { name: 'Alice', score: 42 };

return (
  <p>
    {user.name} ha segnato {user.score} punti.
  </p>
);
```

Il valore dentro `{}` può essere una stringa, un numero, un array o qualsiasi espressione che produce un valore. Gli **statement** — `if`, `for`, `while` — non producono valori. Usa un ternario o `&&` al loro posto:

```jsx
// ternario: un ramo o l'altro
{isLoggedIn ? <Dashboard /> : <Login />}

// short-circuit: renderizza solo quando vero
{hasError && <ErrorBanner message={error.message} />}
```

### Differenze negli attributi

Gli attributi JSX seguono le regole di denominazione di JavaScript, non di HTML. Le due differenze che incontrerai in ogni progetto:

| HTML | JSX | Motivo |
|---|---|---|
| `class="btn"` | `className="btn"` | `class` è una parola riservata in JS |
| `for="email"` | `htmlFor="email"` | `for` è una parola riservata in JS |
| `<br>` | `<br />` | Ogni tag deve chiudersi |
| `<input>` | `<input />` | Ogni tag deve chiudersi |

Tutti gli altri attributi comuni — `id`, `href`, `src`, `style`, `aria-*`, `data-*` — si scrivono identicamente a HTML.

<Callout type="warn">
Passare `class` invece di `className` non genera un errore in JSX — scrive silenziosamente l'attributo sbagliato nel DOM, nessun CSS viene applicato, e il bug può essere invisibile finché non apri il DevTools. Il Playground 2 qui sotto te lo mostrerà di persona.
</Callout>

### Tag self-closing

In JSX, **ogni tag deve chiudersi** — sia con un tag di chiusura corrispondente, sia con uno slash prima del `>`:

```jsx
<img src="/logo.svg" alt="Next Academy" />
<input type="email" name="email" />
<hr />
<br />
```

### Fragment e la regola della radice singola

Un componente può restituire solo **un elemento radice**. Questo fallisce:

```jsx
// SyntaxError: Adjacent JSX elements must be wrapped in an enclosing tag.
return (
  <h1>Titolo</h1>
  <p>Sottotitolo</p>
);
```

La soluzione ovvia è un `<div>` contenitore — ma aggiunge un nodo inutile al DOM e può rompere i layout (specialmente in tabelle e container flex/grid). I **Fragment** raggruppano gli elementi senza aggiungere nulla al DOM reale:

```jsx
return (
  <>
    <h1>Titolo</h1>
    <p>Sottotitolo</p>
  </>
);
```

`<>...</>` è la forma breve di `<React.Fragment>...</React.Fragment>`. Usa la forma nominata quando devi passare una prop `key` (ad es. dentro un `.map()`):

```jsx
items.map((item) => (
  <React.Fragment key={item.id}>
    <dt>{item.term}</dt>
    <dd>{item.definition}</dd>
  </React.Fragment>
));
```

## Da JSX al DOM reale

Quando il tuo componente restituisce JSX, React costruisce un **virtual DOM** — un albero leggero di semplici oggetti JavaScript che rispecchia la forma della UI che hai descritto.

Al primo render, React converte quest'albero in nodi DOM reali. Ad ogni render successivo, fa il **diff** del nuovo albero virtuale con il precedente e applica solo il minimo insieme di modifiche — un processo chiamato **riconciliazione**.

```
Il tuo JSX
  ↓ compilatore
Chiamate React.createElement
  ↓ render
Albero di oggetti del virtual DOM
  ↓ diff di riconciliazione
Patch minime al DOM reale
```

Non chiami mai `document.createElement` direttamente. Descrivi la UI che vuoi; React trova la sequenza più economica di operazioni DOM per realizzarla.

<Callout type="info">
L'algoritmo completo di riconciliazione — incluso come React decide quando riutilizzare vs. distruggere un nodo DOM — è trattato nella Lezione 4, dove le prop `key` stabili diventano fondamentali. Per ora il modello mentale è sufficiente: React mantiene una copia veloce in memoria e sincronizza il DOM reale nel modo più efficiente possibile.
</Callout>

## Punti chiave

<Callout type="tip">
**JSX è zucchero sintattico per `React.createElement`.** Ogni espressione tra parentesi angolari compila in una semplice chiamata di funzione che restituisce un oggetto JavaScript. Capirlo rende gli errori JSX ovvi e il debugging diretto.

**Tre regole sugli attributi:** `className` non `class`, `htmlFor` non `for`, e ogni tag deve chiudersi con `/>` o un tag di chiusura corrispondente. Producono fallimenti silenziosi — non errori — il che li rende facili da perdere.

**Una radice, sempre — usa i Fragment.** `<>...</>` raggruppa i fratelli senza aggiungere nodi DOM. È essenziale in tabelle, liste e container flex/grid dove un `<div>` extra in più rompe il layout.

**Tu descrivi; React decide.** Il virtual DOM e l'algoritmo di riconciliazione applicano solo le patch DOM necessarie. Non tocchi mai `document` direttamente — questa è l'astrazione che JSX e React ti danno.
</Callout>
