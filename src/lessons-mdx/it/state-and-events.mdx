# Stato ed Eventi

Lo stato è il modo in cui React ricorda le cose tra un render e l'altro. Ogni UI interattiva — un contatore, un form, un toggle — è alimentata dallo stato.

## Cos'è lo stato

Una variabile JavaScript normale si azzera ad ogni render. React chiama di nuovo la tua funzione componente ogni volta che deve aggiornare lo schermo; qualsiasi dichiarazione `let` reinizia da capo ogni volta:

```jsx
// ❌ Non funziona mai — count si azzera a 0 ad ogni render
function Counter() {
  let count = 0;
  return (
    <button onClick={() => { count += 1; console.log(count); }}>
      Count: {count}
    </button>
  );
}
```

Il click sul bottone scatta, `count` raggiunge 1, ma lo schermo non cambia mai — React non sa che è successo niente. Lo stato è la soluzione: React lo conserva *fuori* dalla tua funzione e restituisce il valore corrente ad ogni render:

```jsx
import { useState } from 'react';

function Counter() {
  const [count, setCount] = useState(0);

  return (
    <button onClick={() => setCount(count + 1)}>
      Count: {count}
    </button>
  );
}
```

Chiamare `setCount` dice a React "ri-renderizza questo componente". React chiama di nuovo la tua funzione — e questa volta restituisce il nuovo valore di `count`.

## Dichiarare lo stato con useState

```jsx
const [valore, setValore] = useState(valoreIniziale);
```

- `valore` — lo snapshot corrente dello stato per questo render.
- `setValore` — chiamalo per programmare un re-render con un nuovo valore.
- `valoreIniziale` — usato solo al primo render; può essere un numero, stringa, oggetto, array o `null`.

**Due regole per gli hook:**
- Chiama `useState` (e tutti gli hook) **al livello superiore** del tuo componente — mai dentro `if`, cicli o funzioni annidate.
- Chiama gli hook solo all'interno di componenti funzionali React o hook personalizzati.

React identifica ogni pezzo di stato dall'ordine in cui viene chiamato `useState`. Cambiare quell'ordine tra i render rompe la corrispondenza tra le chiamate e i valori memorizzati.

## Gli aggiornamenti di stato sono asincroni

Chiamare un setter non aggiorna la variabile immediatamente. React programma un re-render e il nuovo valore è visibile solo nel *render successivo*. Il valore del render corrente è fisso — è una costante:

```jsx
function Counter() {
  const [count, setCount] = useState(0);

  function handleClick() {
    setCount(count + 1);
    console.log(count); // ⚠️ È ancora 0 — il render non è ancora avvenuto
  }

  return <button onClick={handleClick}>Count: {count}</button>;
}
```

<Callout type="warn">
`console.log(count)` subito dopo `setCount` stampa sempre il **vecchio valore**. `count` è una costante legata all'inizio di questo render — nulla può cambiarla a metà funzione. Il valore aggiornato appare solo quando React ri-renderizza e la tua funzione viene eseguita di nuovo.

Questo significa anche che chiamare `setCount(count + 1)` più volte nello stesso handler incrementa solo una volta — ogni chiamata legge lo stesso snapshot obsoleto:

```jsx
// ❌ count inizia a 0 — tutte e tre le chiamate leggono 0, il risultato è 1
setCount(count + 1);
setCount(count + 1);
setCount(count + 1);
```

Usa la forma dell'updater funzionale per concatenare più aggiornamenti correttamente.
</Callout>

## La forma dell'updater funzionale

Quando il valore successivo dipende da quello precedente, passa una funzione invece di un valore:

```jsx
setCount(prev => prev + 1);
```

React mette in coda queste funzioni e le applica in ordine, ognuna ricevendo il risultato della precedente:

```jsx
// ✅ Ogni updater riceve l'ultimo prev — il risultato è 3
setCount(prev => prev + 1);
setCount(prev => prev + 1);
setCount(prev => prev + 1);
```

Usa la forma funzionale ogni volta che:
- Chiami il setter più volte in un handler.
- Il nuovo stato dipende dallo stato corrente.
- Sei dentro un `setTimeout`, un callback di `fetch`, o qualsiasi funzione asincrona in cui il `valore` catturato potrebbe essere obsoleto.

## Gestori di eventi

React passa un oggetto evento sintetico ad ogni gestore. I pattern più comuni:

```jsx
// onClick — scatta al click
<button onClick={(e) => console.log(e.currentTarget)}>Clicca</button>

// onChange — scatta ad ogni tasto premuto
<input onChange={(e) => setText(e.target.value)} />

// onSubmit — scatta all'invio del form
<form onSubmit={(e) => { e.preventDefault(); invia(); }}>
  ...
</form>
```

**`e.preventDefault()`** blocca l'azione predefinita del browser. Per i form impedisce la navigazione della pagina; per i link impedisce di seguire l'href. Chiamalo prima, prima di qualsiasi aggiornamento di stato.

Definisci i gestori come funzioni con nome quando la logica occupa più di una riga — mantiene il JSX leggibile e rende la funzione facile da testare:

```jsx
function handleChange(e) {
  const tagliato = e.target.value.trimStart();
  setText(tagliato);
}

return <input onChange={handleChange} />;
```

Passa il *riferimento* alla funzione, non una chiamata: `onChange={handleChange}`, non `onChange={handleChange()}`. La seconda forma viene eseguita immediatamente ad ogni render.

## Non mutare mai lo stato direttamente

React rileva i cambiamenti per uguaglianza di riferimento. Mutare un oggetto o array esistente non crea un nuovo riferimento — React vede lo stesso valore e salta il re-render:

```jsx
// ❌ Mutazione — React vede lo stesso oggetto, nessun re-render
const next = state;
next.count += 1;
setState(next);

// ✅ Nuovo oggetto — React vede un riferimento diverso, trigger re-render
setState({ ...state, count: state.count + 1 });
```

### Pattern di aggiornamento immutabile

**Oggetto — aggiornare un campo:**
```jsx
setState(prev => ({ ...prev, nome: 'Alice' }));
```

**Array — aggiungere un elemento:**
```jsx
setItems(prev => [...prev, nuovoElemento]);
```

**Array — rimuovere un elemento:**
```jsx
setItems(prev => prev.filter(item => item.id !== idTarget));
```

**Array — aggiornare un elemento:**
```jsx
setItems(prev =>
  prev.map(item => item.id === idTarget ? { ...item, fatto: true } : item)
);
```

Il pattern è sempre: produci o deriva un *nuovo* valore — non modificare mai quello che React già possiede.

## Playground 3 — Lista di attività

L'input di testo è un **componente controllato** — il suo `value` viene sempre letto dallo stato, e ogni tasto aggiorna lo stato tramite `onChange`. ## Punti chiave

<Callout type="tip">
**Lo stato è memoria fuori dalla funzione.** Le variabili locali si azzerano ad ogni render; lo stato persiste. React lo conserva, il tuo componente lo legge, e chiamare il setter programma il prossimo render.

**Gli aggiornamenti di stato sono snapshot, non mutazioni.** Ogni render cattura il proprio valore di ogni variabile di stato. Chiamare un setter programma un re-render — il valore corrente non cambia mai a metà render. `console.log(valore)` dopo un setter mostra sempre lo snapshot vecchio.

**Usa l'updater funzionale quando il nuovo stato dipende da quello vecchio.** `setX(prev => ...)` è la forma corretta quando chiami il setter più volte in un handler, in codice asincrono, o ovunque non puoi garantire che il valore catturato sia aggiornato.

**Non mutare mai oggetti o array nello stato.** Produci sempre un nuovo valore: spread degli oggetti, spread degli array per aggiungere, `filter` per rimuovere, `map` per aggiornare. La mutazione aggira il rilevamento delle modifiche di React e lascia la UI desincronizzata.

**`e.preventDefault()` prima.** Per gli invii di form e i click sui link, chiamalo prima di qualsiasi aggiornamento di stato per bloccare la navigazione predefinita del browser.
</Callout>
